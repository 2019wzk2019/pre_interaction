# 预交互伸手识别：电容屏与 IMU

答辩用讲解稿。任务是在手机上判断手从哪一侧伸向屏幕，用来提前点亮对应半屏。三类标签：`左to右`、`右to左`、`others`。

- `左to右`：手从屏幕左侧伸入（够向右下）→ 建议亮右半屏
- `右to左`：手从屏幕右侧伸入（够向左下）→ 建议亮左半屏
- `others`：握持、静置、点击、伸手后的回程

两条传感器路线都做到了可上机的模型包：电容触控（TP）和惯性测量（IMU）。交付物是 ONNX 加一份给鸿蒙同事的 IO 说明，不是只留训练脚本。

---

## 1. 问题为什么值得做

普通触控要等手指按下才有事件。伸手过程中，屏幕其实已经能看到两种更早的信号：

1. **电容差分**。厂商每约 12ms 送一帧 34×21 的一阶差分，外加一段 LineData。手还没形成稳定点击时，长边附近的格子已经在变。
2. **IMU**。加速度（带重力，m/s²）和角速度（rad/s）。伸手是一次短促的转动，和静握、点击的运动模式不同。

预交互的价值是把「手已经在来」变成半屏预亮，而不是等 Down 事件。难点不在把滑动方向分开，而在 **others 不能乱亮**：握持、点击、回程都会带动作，裸 argmax 会闪灯。

## 2. 数据

| 来源 | 内容 | 用法 |
|------|------|------|
| 早期采集 `data/tp/train`、留出 `data/tp/test` | 连续 IMU + `diffdata_continuous.jsonl`（TP 差分） | TP 模型的训练与留出 |
| 上午短录音 `data/imu_old`（`l2r_*`） | 单次伸手，约 0.6–1.3s | IMU：整段 onset 之后标成该方向 |
| 下午双段录音 `data/imu_new`（`test_*`） | 约 1.4–2.6s，前半伸手、后半回程 | IMU：前半是方向，后半是 others |
| 独立 OTHERS 长录音 | 约 16–29s | 按时间切：前 70% 训练，后 30% 测试 |

电容真值文件的格式是 jsonl：第一行 `schema = preinteraction.diffdata.v1`，之后每帧一个 `raw` 字符串，34 行 × 21 列，行优先。同目录里名叫 `*_tp.csv` 的文件经常其实是 IMU，名字不可靠，要看表头里有没有 `kind=acc/gyro`。

IMU 伸手录音不能整段当正样本。开头有一段静握，角速度模长接近基线。做法是用前 0.12s 估计噪声，阈值 `baseline + max(0.05, 5σ)`，连续抬升才算 onset，只保留 onset 到结束。双段文件再在时间中点切开：前半做 onset 切割并标方向，后半整段标 others，不再切 onset。

## 3. 电容路线：从随机森林到单帧卷积

### 3.1 随机森林基线

早期上机模型是随机森林。500ms 滑窗里对差分做统计，只留竖屏左右长边各 3 列，拼成 **1021 维**，丢掉中区和 LineData。它能用，但特征是手写的，和「全屏空间形状」绑得不紧，换一版归一化或维数就会和 App 对不上（1127 维全网格 vs 1021 维截边，曾经直接导致推理维数错误）。

### 3.2 第一版深度学习为什么更差

第一版 ConvNet 把 500ms 重采样成 42 帧，时间当作通道，张量 `(B, 42, 34, 21)`。它比随机森林差，原因不是「网络容量不够」，而是任务设定偏了：

- 时间被压进通道，网络看不到「这一帧的空间形状」，却要记一段轨迹。
- 验证集里 others 覆盖不足，左右伸手的召回看起来高，握持会被打成滑动。
- 没有按帧做尺度归一化，差分幅值随握力和噪声漂。
- 有一版还做了窗内 cumsum。积分把噪声和握持漂移叠进电平，和「伸手是局部变化」这个事实相反。

### 3.3 改成全屏单帧之后

和随机森林对齐的正确归纳偏置是：**每一帧差分本身就带方向**。长边哪一侧在变，比 500ms 轨迹更直接。

最终 TP 网络：

| 项 | 设定 |
|----|------|
| 输入 | `(1, 1, 34, 21)`，全屏，不截边 |
| 内容 | 原始一阶差分，**不做 cumsum** |
| 归一化 | 这一帧 714 个数除以自身标准差，不减均值 |
| 输出 | 3 类 logits，推理前 softmax |
| 参数量 | 185,635 |
| 留出准确率 | **99.96%**（`data/tp/train` 训练，`data/tp/test` 留出） |

点击类仍可能偶发误报，所以上机不裸 argmax。门控要求概率过阈值，并且最近 5 次里至少 3 次同一侧才亮灯。

这个对比是答辩里最值得讲的一点：深度模型输给随机森林时，先查输入契约（窗长、是否积分、有没有 others、归一化），而不是先加层。

## 4. IMU 路线：短窗一维卷积

TP 依赖厂商差分回调。IMU 不依赖触控固件，适合作为另一条预交互通道。加速度必须用**带重力**的版本，不能换成线性加速度。

网络是 1D ConvNet，输入 `(B, 6, T)`，通道顺序 `ax, ay, az, gx, gy, gz`。结构：6→32→64，池化，→96，全局平均池化，再线性到 3 类。约 **30,307** 参数。每个窗同样是整窗除以标准差，不减均值。采样重采样到 100Hz，步长 10ms。真机不做 onset 切割，只滑最近一个窗。

窗长对比（同一结构，录音级留出）：

| 窗长 | 窗口准确率 | 文件多数票 |
|------|------------|------------|
| 100ms | **92.5%** | 7/7 |
| 200ms | 90.1% | 全对 |
| 300ms | 88.9% | 全对 |

100ms 最好。伸手是一次短促转动，窗拉长会把静握和回程卷进来。

后来把上午短录音和下午双段录音合在一起重训 100ms（`data/imu_old` 21 条 + `data/imu_new` 22 条，含一条新的高运动 OTHERS）：

- 训练窗 7842，测试窗 3294
- 窗口准确率 **93.1%**
- 片段多数票 **21/21**
- 左to右 recall 0.989，右to左 recall 1.000，others recall 0.916

混淆的主要方向是 **others → 滑动**，左右之间几乎不混。回程后半段仍可能被投成伸手，所以亮灯门控保留，和 TP 同一套思路。

## 6. 悬浮：用积分还是用原始差分

手指不接触、停在屏幕上方时，电容仍有弱信号。两种表示回答的不是同一个问题。

- **原始一阶差分**适合「正在靠近或离开」。手停住之后，帧间差分回到噪声，悬浮斑会消失。现有伸手模型吃的就是 raw diff，这条不用改。
- **从录像起点无界 cumsum** 能把静止接触留在图上，但噪声和握持漂移会一直积分（实测电平可到数万），起点不同，电平就不同，不适合做模型输入。
- **悬浮态**更合理的是短时或漏积分：例如 100–300ms 的差分求和，或 `level ← level + diff − α·level`，再减去一个更慢的底板。这样「人还在上方」留得住，基线不会无限漂。判据看空间形状和能量，避免把噪声积成假斑。

若后续做悬浮分类，输入应是这个漏积分后的 34×21 单帧，而不是把整段 cumsum 当作时间通道。

---

## 7. 局限与下一步

- 数据量仍是实验规模：IMU 左右各约二十次伸手，留出是按文件抽的，还不是跨用户、跨握姿的大测试。
- others 的精确率高、召回略低。亮灯安全，但回程和部分握持仍会短暂像滑动，必须靠门控而不是单帧。
- TP 99.96% 是现有测试集上的留出，不能外推成「任何握持都不误报」。
- 悬浮还没有标注集，也没有对照实验。第 6 节是下一步的输入设计，不是已完成的模型。
- 电容回调和 IMU 时钟经常对不齐（曾看到约数秒到十几秒的偏差），融合模型前要先对齐时间，不能按文件名假设同步。

下一步若继续做：先采「悬浮 / 实按 / 空握」对照，用漏积分单帧训一个三分类，和现有 raw-diff 伸手模型并列，而不是替换它。

## 8. 可能被问到的点

**为什么不用一个模型吃 TP 和 IMU？**  
两路采样、时钟和缺失情况都不同。分开部署已经能各自亮灯；融合要先解决对齐，否则只会把一路的错误带进另一路。

**深度学习是不是一定好于随机森林？**  
不是。500ms 时间当通道、没有 others、没有按帧归一化时，卷积网不如 1021 维随机森林。改成全屏单帧差分加 per-sample std 之后，留出到 99.96%，同时去掉了手写截边特征。

**为什么 IMU 用 100ms 而不是更长？**  
200ms、300ms 窗口准确率下降。伸手持续时间就在几百毫秒量级，长窗把静握和回程算进同一个标签。

**上机为什么不在设备上做 onset 切割？**  
onset 是离线清洗标签的办法。在线每 10ms 推最近 100ms，门控负责不闪。若在线先等 onset，预亮会晚一截，预交互就没了。

**cumsum 图上能看到手，为什么模型不用？**  
可视化用 cumsum 是为了把接触斑留在格子上。模型要的是「这一帧变了没有、变在哪一侧」。无界积分把漂移变成特征，悬浮如果要电平，应该用带遗忘的短积分，而不是整段累加。
